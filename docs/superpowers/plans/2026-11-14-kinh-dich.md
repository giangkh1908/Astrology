# Kinh Dịch (gieo xu + lời kinh + AI luận) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `/kinh-dich`. The user types a question. The AI clarifies it with AskCard before the cast. The user casts 3 coins × 6. The AI reads the hexagram in detail from the pre-computed scripture text and a memory branch that belongs to Kinh Dịch only.

**Architecture:**
- Pure core in `lib/kinh-dich/` (casting, hexagram computation, focus rule, scripture lookup from JSON ported from dich-so).
- Its own store port `KinhDichStore` (neon/memory/disabled adapters), sharing the `conversations/messages/ai_requests` tables with kind `kinhdich`. Migration 004.
- One route `/api/kinh-dich` reuses `streamChatResponse` + `askUser`. The phase is decided by stored state.
- A client page that reuses AskCard.

**Tech Stack:** Next.js 16 App Router, React 19, TS, Neon, tsx + node:assert regression tests.

**Spec:** `docs/superpowers/specs/2026-11-14-kinh-dich-design.md`

## Global Constraints

- Login is required (`callerOf`). owner = `caller.kind==='member' ? userId : null`.
- **One cast = 1 credit:**
  - charge 1 when the cast is opened;
  - clarification (at most 4 AI turns before the cast) is free;
  - the first reading after the cast is free;
  - every follow-up question costs 1;
  - answering an ask card is free when `answering:true` and the last assistant message has status `asked`.
- The Kinh Dịch memory reads only kind `kinhdich` of the right owner. Limits: 30 entries, 4000 characters, 500 characters per entry, 1.5 s timeout → empty.
- The prompt contains this exact line: "không được tự đổi quẻ hay tự chế lời kinh".
- Hào từ is labelled "theo bản dịch Ngô Tất Tố". `modern` is labelled as the dich-so project's modern commentary (CC BY 4.0), never as Ngô Tất Tố's words.
- Tests use fake data. Never touch the real DB or the user's dev server.
- CRLF files: use `scratchpad/edit.js` or the Edit tool. Write new files with Write.

## Review Focus

1. **A client sends `lines` again after the cast to change the hexagram.** The server ignores them and reads from the store. Covered by the route test "lines sau khi gieo bị bỏ qua".
2. **Two concurrent cast requests.** `saveLines` is atomic (`where meta->>'lines' is null`), so only one wins. The other gets 409. Covered by the store test.
3. **A wrong castId, or someone else's castId.** Returns 404 and leaks nothing. Covered by the route test.
4. **The user skips the card or keeps typing instead of answering.** `trailingAsks` caps it, then the AI must state the question is clear. Covered by the prepare test.
5. **Store disabled.** The route still works from the body and stores nothing. Covered by the route test.

### Task 4: Route `/api/kinh-dich`

**Files:**
- Create: `app/api/kinh-dich/route.ts` (POST + GET)
- Test: `scripts/regression/kinh-dich-route.test.ts` (fake fetch like `interpret-ask-route.test.ts`)

**Interfaces:**
- **Consumes:** Tasks 1–3, `chargeChat`, `refundingOnFinish`, `withQuotaHeader`, `streamChatResponse`, `askToPlainText`, `trailingAsks`, `MAX_CONSECUTIVE_ASKS`.
- **Produces:**
  - POST `{castId?, messages, lines?, answering?}` returns SSE with headers `X-Cast-Id` and `X-Chat-Quota`.
  - Errors: 401 / 400 / 404 / 409.
  - GET `→ {casts: CastSummary&{main?:string; changed?:string}[]}`.
  - GET `?castId= → {cast: CastRecord, reading?: Cast}`.

**Phase logic:**
- **No castId:** charge 1 → `createCast` → prepare.
- **Not yet cast, no lines:**
  - `assistantCount >= 4` → 409 "Câu hỏi đã đủ, hãy gieo quẻ.";
  - otherwise prepare, free.
- **Not yet cast, with lines:**
  - `parseLines` fails → 400;
  - `saveLines` false → 409;
  - otherwise reading with the hidden `READING_QUESTION`, free.
- **Already cast:** follow-up questions are charged, unless the free answer rule applies.
- **Message history:** messages are taken from the store (`cast.messages`) plus the last user message in the body. The client's assistant messages are never trusted.
- **askUser:**
  - prepare: `trailingAsks < MAX`;
  - reading: false;
  - follow-up: `trailingAsks < MAX`.
- **Store disabled:** stateless. A body with lines → reading from the body's messages; otherwise prepare. `chargeChat` every turn.

**Steps:**
- [ ] **Write the failing tests:**
  - 401 without a cookie.
  - 400 for an empty question or one over 500 characters.
  - The first turn returns `X-Cast-Id` and the request carries the `hoi_nguoi_dung` tool; the prepare prompt is in the system message.
  - A member's quota: open the cast −1; answer the card 0; the reading 0; a follow-up −1.
  - 409 when lines are sent twice.
  - Lines sent after the cast with different values: the prompt still holds the old hexagram.
  - Another owner's castId → 404.
  - Store disabled: works and has no `X-Cast-Id`.
  - The memory in the system prompt of the 2nd cast holds the 1st cast's question and no `interpret` question.
- [ ] **Run** → FAIL.
- [ ] **Implement.**
- [ ] **Run** → PASS. Register the test. Run `npm run harness:quick` → exit 0.
